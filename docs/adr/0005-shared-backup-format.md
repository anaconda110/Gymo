# ADR 0005：跨端备份格式以共享文档为规范源

日期：2026-10-10
状态：已接受

## 背景

两个客户端的备份格式互不兼容（见 issue #1）：Android 导出 Room 实体结构
（`sessions`/`workoutExercises`/`type`/`orderIndex` 等命名，无信封），Web 导出
Dexie 表结构（外层带 `app`/`version` 信封）。跨端迁移目前只能人工转换，而
`CONTEXT.md` 把备份定义为「数据主权的兑现方式」——其可用性不应取决于用户
恰好拿着哪台设备。

需要决定：规范放在哪里、字段谁向谁靠、以及如何处理两端的能力差。

## 决策

1. **规范源是一份与实现无关的文档**（`docs/BACKUP-FORMAT.md`），不是某一端的
   实现。两端各自写适配器向它靠拢；实现与文档冲突时以文档为准。
2. **字段形状取 Web 侧**：Web 的表结构（`workouts`/`workoutExercises`/`sets`，
   `order`/`setType`/`date` 命名）覆盖面更大，且已被 19 条 e2e 覆盖；Android
   侧改名为迁移成本的一侧，且它本来就有一次待做的迁移（当前是 legacy 形态）。
3. **信封独立版本**：新增整数 `schemaVersion`（当前 1）与 `producer` 字段。
   `producer` 只作诊断，不作为分支解析的依据——否则每端都要理解每端的怪癖，
   规范就失去意义。真正需要的差异一律用规范字段显式表达。
4. **单位固定 kg、时间固定 epoch 毫秒**：显示层的磅不进入备份文件。
5. **缺失即未记录**：不用哨兵值。这直接决定导入时"缺 RPE"与"RPE 为 0"是两件事。
6. **能力差按有损处理并显式告知**：Web 有而 Android 没有的概念
   （RPE、单组备注、模板、身体测量、组类型细分、`completedAt`、`image`、
   `workouts.name/notes/durationSec`）导入 Android 时丢弃，但必须在导入结果中
   汇总提示。**不做**字段的降级编码（如把 RPE 塞进 note 字符串），那会污染
   数据、让未来的导入器无法分辨。
7. **legacy 兼容窗口**：导入方可接受 Android 旧格式（无信封），降级规则写在
   规范 §7；导出方一律输出信封 v1，不再产出 legacy。

## 取舍与代价

- **选择「文档为规范」而非「一端为主、另一端从属」**：多写一份文档，换来的是
  未来第三端（如桌面端）加入时不需要先选边站。
- **`producer` 不参与解析**：这让"Android 导入 Android 备份"与"Android 导入
  Web 备份"走同一条代码路径——前提是两端都真正遵守字段规范；代价是迁移期间
  实现要先把自身旧格式翻译成规范形态（Android 侧需要一次真实迁移）。
- **不做有损字段的编码 hack**：跨端往返会丢失 RPE 等信息，用户会觉得"少了"。
  这是有意的：宁可少，不可乱。

## 未决（留待实现时确认）

- Android 的 `sessionId` 是否在规范中保留为别名，以降低 Android 导入器改动量
  （当前规范选择重命名，由导入器做映射）。
- 进行中训练（`endedAt == null`）在 Web 端的语义目前与 Android 不一致，
  是否需要在规范层给出统一判定规则。
- Android 预置动作（34 个中文动作名）与 Web 预置动作（20+ 中英双语）不同源，
  跨端导入后动作字典会并存两套。是否在未来统一种子库，本 ADR 不做决定。
