# ADR 0001：移除对同类产品的品牌引用，改用独立表述

日期：2026-10-06
状态：已接受

## 背景

`README.md` 与 `docs/Gymo项目文档.md` 最初并非以独立作品的方式介绍本项目，而是以某一商业训练 App 作为参照系：声明对其核心体验的模仿、向其开发者致意，并以「贴近其风格」描述视觉取向。文档另有一张逐项对比该产品形态、数据存储、定价与技术栈的表格（`docs` §1.4）。

需要判断这些表述的实际风险，并决定其中哪些信息值得保留。

## 判断

- **受保护的与不受保护的**：功能清单、训练理念、`训练容量 = 组数 × 重量 × 次数` 这类公式属于思想/方法，不受著作权保护，可以自由实现与陈述。对方受保护的是代码、文案、图标与界面外观，以及其注册商标。因此实现本身无风险，风险在表述。
- **名称使用**：在文档中指名提及同类产品，若仅为识别该产品，通常属正当的指名性使用；但一旦与「我们仿制它」的表述结合，就会向「混淆来源」和「搭便车」方向偏移，这正是《反不正当竞争法》关注的区域（含虚假宣传与混淆行为）。复述其定价与技术栈进一步放大了这一关联。
- **本项目形态**：个人、自用、无商业化、无对外发布渠道，实际发生争议的概率很低；但那种表述除法律风险外，还会让读者把项目理解为克隆品，而非独立作品。

## 决策

1. 删除全部同类产品的名称与开发者姓名，以及一切以对方为参照系的表述（模仿、致意、风格贴近）。
2. §1.4 对比表改写为**只描述本项目自身取舍**的表格（维度 / 本项目的选择 / 说明），不再复述他人的定价、技术栈与功能范围。
3. 保留有价值的信息（本项目的本地优先、无账号、离线、开源定位），只换掉表述方式。
4. `Excel`／`Numbers` 保留为指名性使用（用于说明 CSV 能拿什么打开）；`HealthKit` 因本项目并不集成它，改为中性的「可穿戴 / 健康数据集成」，不留第三方的商标名。
5. 该清理**不是**对实现的重命名：产品名 `Gymo`、`IndexedDB` 库名 `gymo-db`、`localStorage` 键、导出文件名与备份文件内的 `app: 'Gymo'` 标记全部保持不变，因而不需要数据迁移，旧备份文件仍可导入。

## 取舍与代价

- **放弃**：与知名同类产品并列带来的「一眼看懂」效果，以及借其名字获得的检索曝光。
- **保留**：所有实质信息（本项目选择做什么、不做什么）都仍在文档里，只是不再通过他人作参照系来表达。
- **未决**：`Gymo` 这一名称在应用商店中已有多个同类应用使用，商业使用前需按地区单独做商标检索；本次不更名，因为个人自用场景下改名收益不足以抵消迁移成本。
- **历史**：清理前的提交历史中仍留有旧表述，故本次以重建仓库历史的方式收尾，旧历史另存于仓库外的 git bundle。

## 备选方案（未采纳）

- **只删致意那一句**：等于保留最具风险的模仿声明与对比表，未解决根本问题。
- **保留一次指名性提及 + 免责声明**：风险高于彻底删除，且对个人项目而言没有必须保留该名字的理由。
