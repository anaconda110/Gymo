# Gymo 需求规划

本文档记录 Gymo 后续迭代的需求清单，按优先级与 feature 分支对应。

---

## P0 — 核心体验完善

### 需求 1：动作库管理
**对应分支**：`feature/exercise-manager`

**背景**：当前动作库为预置 34 个动作，用户无法自定义增删改。

**功能点**：
1. 新增自定义动作：输入名称、目标肌群、类型（杠铃/哑铃/器械/自重）
2. 编辑已有动作：修改名称/肌群/类型
3. 删除动作：软删除（标记 `isCustom=false` 的预置动作不可删，仅可隐藏）
4. 动作搜索：在动作选择弹窗中增加搜索框，按名称/肌群模糊匹配
5. 肌群筛选 Tab：弹窗顶部按肌群横向滚动筛选

**验收标准**：
- 用户可添加自定义动作并立即在选择弹窗中看到
- 编辑后训练历史中的动作名同步更新
- 搜索框输入「卧推」能匹配到「杠铃卧推」「哑铃卧推」等

## P1 — 数据与统计

### 需求 2：训练数据统计
**对应分支**：`feature/workout-stats`

**背景**：用户需要回顾训练量与频率，判断进步趋势。

**功能点**：
1. 统计页（第三个 Tab）：展示总训练次数、总组数、总容量（Σ 重量×次数）
2. 周训练频率热力图（类似 GitHub 贡献图）
3. 单个动作的重量趋势折线图（最近 10 次训练的最大重量）
4. 月度训练量柱状图（按肌群分组）

**验收标准**：
- 统计数据随训练完成实时更新
- 图表在低端机型上滚动流畅（Canvas 绘制或 MPAndroidChart）

---

### 需求 3：数据备份与导出
**对应分支**：`feature/data-backup`

**背景**：换机或重装 App 时数据会丢失，需要备份能力。

**功能点**：
1. 导出：将数据库导出为 JSON 文件（含所有 Session/Exercise/Set）
2. 导入：从 JSON 文件恢复数据（合并策略：按 id 去重，已存在则跳过）
3. 分享：通过系统分享 Sheet 将 JSON 发送到其他 App（微信/邮件等）
4. 自动备份：每次完成训练后自动导出到应用私有目录

**验收标准**：
- 导出的 JSON 可在另一台设备导入后完整还原训练记录
- 导入时不破坏现有数据（id 冲突时跳过而非覆盖）

## P2 — 交互优化

### 需求 4：UI 美化
**对应分支**：`feature/ui-polish`

**背景**：当前 UI 为功能优先，缺乏动效与视觉层次。

**功能点**：
1. 动作卡片添加/删除时使用 `AnimatedVisibility` 过渡动画
2. 组次行添加/删除时使用 `animateItemPlacement` 平滑位移
3. 完成打勾时增加缩放反馈动画
4. 空状态增加插画占位（Lottie 或矢量图）
5. 深色/浅色主题切换（设置页）
6. 训练卡片增加渐变背景与阴影层次

**验收标准**：
- 动画帧率 ≥ 60fps，无卡顿
- 深色模式下文字对比度满足 WCAG AA

---

### 需求 5：组次拖拽排序
**对应分支**：`feature/set-reorder`

**背景**：用户加组顺序可能不对，需要拖拽调整。

**功能点**：
1. 长按组次行进入拖拽模式
2. 拖拽时实时更新 UI 顺序
3. 松手后批量更新数据库 `setIndex`（事务）
4. 拖拽手柄图标（≡）提示可拖拽

**验收标准**：
- 拖拽后 UI 序号与数据库 `setIndex` 一致
- 拖拽过程中其他行平滑避让

## 开发流程

1. 切到对应 feature 分支
   ```bash
   git checkout develop
   git checkout feature/xxx
   ```
2. 按「功能点」逐个实现并提交
3. 自测通过后合并回 `develop`
4. `develop` 整体测试后合并回 `main` 并打 tag
